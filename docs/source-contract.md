# 跨页选择门户
初始有四家单位，每页两行，一家不可选，一家已有标签。“按筛选全选”声明dynamic-all，排除集单独展示。新单位进入会改变generation与可选总数，排序和翻页不改变业务键。
添加标签逐项返回accepted、unchanged、failed，M-B故意暂时锁定。现有查看器只读当前页，不固定选择范围或发起批量操作；执行能力必须通过实际页面流程，不使用页面变量修改来假装处理成功。 门户的业务数据保存在本地来源服务中，关闭或重新打开浏览器不会撤销已接受的写入；页面data-saved可用于等待门户自身保存结束。状态接口只供门户运行，自动化不得直接调用它代替界面操作。

## 固定清单批量标签（src/tags.mjs）
“按筛选全选”是动态集合：确认后若有新单位进入筛选，当前总数不等于已授权范围。自动化因此不把总数当授权，而是把一次预览固化为业务键清单（manifest），并记录筛选条件、generation、可选总数、人工排除项与不可选原因。
- previewScope：在真实页面点击“按筛选全选”、逐项取消人工排除，跨页枚举全部单位后生成预览；预览期间generation或总数变化即报ScopeDriftError，要求重新预览。权限受限（复选框禁用）与不符合筛选的单位单列原因，不进入清单。
- buildManifest / ScopeStore：把确认范围（scopeKeys、excludedKeys）与指纹原子写入本地留存，读取时校验摘要。
- executeConfirmed：执行前重新读取页面并做漂移检测；只有“出现确认时不在清单内的新可选单位”才拒绝继续。单位消失或失去资质不扩大范围，按skipped说明原因。重建选择后再次核对勾选集合与清单一致，点击“添加服务标签”，并校验门户回执的键集合与本轮操作集合完全一致，逐单位保留accepted/unchanged/failed/skipped。
- retryFailed：刷新回到显式选择，只勾选仍在清单内且仍符合条件的失败项；成功与未变结果原样保留，失去资质或已出范围的失败项记为skipped，不做写入。
- reconcile：重启后的只读核对，不点击任何写操作。逐单位给出tagged/untagged/ineligible/tagged-ineligible/missing/excluded/outside-scope结论；人工撤销标签（untagged）被尊重，不会为凑数量自动加回。

## 门户并发与版本约定
门户boot未完成前不渲染、不写入（booted门控），避免新会话用默认数据抢先保存覆盖服务端状态。persist中的saveSeq仅用于判定哪次请求最新，POST体里的generation始终是业务版本号而不是保存序号；因此跨浏览器会话的generation单调延续，可用于检测确认后的结果变动。页面另提供“人工撤销标签”和“人工取消/恢复资质”入口，均走真实点击并触发保存，供演示人工干预后的核对。
